# Parallel BFS and Single-Source Shortest Paths on Large Sparse Graphs with MPI

CS 5220 Final Project — Cornell University, Spring 2026.

This repository contains MPI-based parallel implementations of Breadth-First Search (BFS) and Single-Source Shortest Paths (SSSP) for large sparse graphs, with both 1D row-based and 2D checkerboard graph partitioning strategies.

**Authors:** Felix Grimm (`fjg45`), David Valarezo (`dev38`), Charles Liggins (`cll258`)

## Interactive Session

All experiments must run inside a Perlmutter allocation:

```bash
salloc --nodes 2 --qos interactive --time 01:00:00 --constraint cpu --account=m4341
```

For weak scaling at 64 ranks, use `--nodes 4`.

## Preprocessing: Find the Largest Connected Component

Before running BFS/SSSP, generate an LCC info file that identifies the largest connected component and samples 16 random source vertices from it:

```bash
./build/serial_preprocess --graph $SCRATCH/graphs/com-lj.ungraph.txt --output com-lj_lcc.txt
./build/serial_preprocess --graph $SCRATCH/graphs/roadNet-CA.txt --output roadNet-CA_lcc.txt
```

The output file contains `n_lcc`, `m_lcc`, and a list of source vertices.

---

## Running BFS

**1D BFS:**

```bash
srun -n 16 ./build/parallel_bfs $SCRATCH/graphs/ca-GrQc.txt bfs1d 67
```

**2D BFS** (requires perfect square number of ranks):

```bash
srun -n 4 ./build/parallel_bfs $SCRATCH/graphs/ca-GrQc.txt bfs2d 67
```

Flags:

- `--lcc-info <file>`: pass the LCC info file for accurate TEPS calculation
- `--no-output`: skip writing the distance file (use for timing runs)

## Checking Load Balance

Verify that ranks have roughly equal edge counts after vertex permutation:

```bash
srun -n 16 ./build/parallel_bfs $SCRATCH/graphs/com-lj.ungraph.txt stats2d
```

## Correctness Verification

1. Run the serial Dijkstra reference implementation:

   ```bash
   ./build/serial_reference --graph $SCRATCH/graphs/ca-GrQc.txt --source 67 --unweighted --output results.txt
   ```

2. Run the parallel BFS to produce a distance file:

   ```bash
   srun -n 4 ./build/parallel_bfs $SCRATCH/graphs/ca-GrQc.txt bfs2d 67
   ```

3. Compare:

   ```bash
   python3 scripts/verify.py results.txt bfs2d_ca-GrQc_src67.txt
   ```

## Weak Scaling Experiments

1. Generate R-MAT graphs at multiple scales:

   ```bash
   python3 scripts/generate_graph.py 18
   python3 scripts/generate_graph.py 20
   python3 scripts/generate_graph.py 22
   python3 scripts/generate_graph.py 24
   ```

2. Preprocess each to find the LCC:

   ```bash
   ./build/serial_preprocess --graph $SCRATCH/graphs/graph_s18.txt --output graph_s18_lcc.txt
   ./build/serial_preprocess --graph $SCRATCH/graphs/graph_s20.txt --output graph_s20_lcc.txt
   ./build/serial_preprocess --graph $SCRATCH/graphs/graph_s22.txt --output graph_s22_lcc.txt
   ./build/serial_preprocess --graph $SCRATCH/graphs/graph_s24.txt --output graph_s24_lcc.txt
   ```

3. Run the weak scaling script from the repo root:

   ```bash
   bash scripts/weak_scaling.sh
   ```

Configurations: 1 rank @ scale 18, 4 ranks @ scale 20, 16 ranks @ scale 22, 64 ranks @ scale 24 (keeping ~4M edges per rank constant).

## Notes

- Graphs are treated as undirected (each edge stored in both directions). TEPS is computed using `m_lcc` from the preprocessing step, which matches the directed edge count in the CSR representation.
- The 2D partitioning requires a perfect square number of MPI ranks (1, 4, 16, 64, 256).
- All graph files live in `$SCRATCH/graphs/` on Perlmutter.
- Delta-stepping SSSP assumes uniformly random edge weights synthesized via a 64-bit mix hash of the endpoint IDs.
